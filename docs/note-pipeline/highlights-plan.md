# 見どころ下調べ 導入計画（2026-11-14 合意、未実装）

ユーザーと合意した設計。実装は別チャットで行う。

## 目的

ネタ候補の段階で、記事に入れると面白い・目を引く要素（見どころ）を下調べしてページに並べ、ユーザーが選ぶ。執筆チームは選ばれた見どころを柱に、裏取りと肉付けから始める（一から調べ直さない）。

## 見どころの形

各候補に `highlights` 配列を付ける。

```json
{"id": "h1", "headline": "一言の見出し（例：過去3回のTOBプレミアム平均は◯%）",
 "evidence": "根拠の数字と出典を1行", "source": "URL または資料名",
 "type": "数字 | 歴史の事例 | 意外な事実 | 用語のたとえ | 他社比較 | 図にできるネタ"}
```

- 本数: 通常記事の候補は3〜5点、有料記事（週末）の候補は5〜10点。平日の候補を長文で選んだ場合は、執筆側で見どころを足す。
- 数字は出典付きのものだけ。売買推奨の表現は使わない（editorial-rules.md に従う）。

## 流れ

- 平日（候補10本）: 11:47 開始・12:10 に候補を掲載（今どおり）→ そのまま見どころ下調べ → 12:40ごろまでに各候補へ見どころを書き足す（2段階掲載）。前場データ（11:35取得）を使うので開始は早めない。
- 週末（候補5本）: 8:05 開始（新天地メルマガ分析 7:27〜 と重ならないように）→ 8:35ごろ候補を掲載 → 9:30 までに見どころを書き足して通知。締切 16:00、執筆 16:30。
- 下調べの担当: 話題・用語は note-market-analyst、銘柄は note-stock-analyst（または note-jp-equity）。トークン節約のため Web 検索は候補1本あたり2〜3回まで。

## ページ（picker.html / weekend-picker.html）

- 候補を選ぶと、その下に見どころがチェックボックスで出る。初期値は全部オン（外したいものだけ外す）。
- 候補ごとに「これも入れて」の自由記述欄（1行〜数行）。
- 見どころがまだ届いていない候補は「見どころを調べています（12:40ごろ／9:30ごろ）」と表示。
- picks に保存する形（例）: 平日 `{"ids": [...], "long": ..., "free": ..., "highlights": {"c2": ["h1", "h3"]}, "extra": {"c2": "自由記述"}}`、週末 `{"id": "w3", "free": ..., "highlights": ["h1", "h2"], "extra": "自由記述"}`。

## 執筆側

- daily-task-prompt.md / weekly-paid-prompt.md: 選ばれた見どころと「これも入れて」を `picks.json` に入れて深掘り担当・証券アナリストに渡す。
- 深掘り担当は見どころの裏取りと肉付けから始める。証券アナリストは選ばれた見どころを全部本文に入れる。PM のレビューに「選ばれた見どころが入っているか」を追加。
- note-pm.md のモード4・6: 候補に見どころの下調べ方針（何を調べると面白いか）を付ける。
