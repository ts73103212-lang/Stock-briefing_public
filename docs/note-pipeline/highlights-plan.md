# 見どころ下調べ 導入計画（2026-11-14 合意、2026-11-14 実装済み）

ユーザーと合意した設計。実装先: `candidates-task-prompt.md`・`weekend-candidates-prompt.md`（フェーズ4・5）、`daily-task-prompt.md`・`weekly-paid-prompt.md`（選ばれた見どころの受け渡し）、`picker.html`・`weekend-picker.html`、`.claude/agents/note-pm.md`（`highlight_plan`・レビュー項目7）、`note-market-analyst.md`・`note-jp-equity.md`（モード: 見どころ）、`note-stock-analyst.md`・`note-securities-analyst.md`。

実装で決めた細部: 日の文書に `highlights_status`（pending / done / partial / failed）と `highlights_eta` を持たせ、ページの表示を切り替える。下調べは2体（相場分析・日本株）で並列。検査は進行役がスクリプトで行う（空の項目・推奨表現を外すだけ）。

## 目的

ネタ候補の段階で、記事に入れると面白い・目を引く要素（見どころ）を下調べしてページに並べ、ユーザーが選ぶ。執筆チームは選ばれた見どころを柱に、裏取りと肉付けから始める（一から調べ直さない）。

## 見どころの形

各候補に `highlights` 配列を付ける。

```json
{"id": "h1", "headline": "一言の見出し（例：過去3回のTOBプレミアム平均は◯%）",
 "evidence": "根拠の数字と出典を1行", "source": "URL または資料名",
 "type": "数字 | 歴史の事例 | 意外な事実 | 用語のたとえ | 他社比較 | 図にできるネタ"}
```

- 本数: 通常記事の候補は3〜5点、有料記事（週末）の候補は5〜10点。平日の候補を長文で選んだ場合は、執筆側で見どころを足す。
- 数字は出典付きのものだけ。売買推奨の表現は使わない（editorial-rules.md に従う）。

- 週末（候補5本）: 8:05 開始（新天地メルマガ分析 7:27〜 と重ならないように）→ 8:35ごろ候補を掲載 → 9:30 までに見どころを書き足して通知。締切 16:00、執筆 16:30。
- 下調べの担当: 話題・用語は note-market-analyst、銘柄は note-stock-analyst（または note-jp-equity）。トークン節約のため Web 検索は候補1本あたり2〜3回まで。

## ページ（picker.html / weekend-picker.html）

- 候補を選ぶと、その下に見どころがチェックボックスで出る。初期値は全部オン（外したいものだけ外す）。
- 候補ごとに「これも入れて」の自由記述欄（1行〜数行）。
- 見どころがまだ届いていない候補は「見どころを調べています（12:30まで／9:30ごろ）」と表示。
- picks に保存する形（例）: 平日 `{"ids": [...], "long": ..., "free": ..., "highlights": {"c2": ["h1", "h3"]}, "extra": {"c2": "自由記述"}}`、週末 `{"id": "w3", "free": ..., "highlights": ["h1", "h2"], "extra": "自由記述"}`。

## 執筆側

- daily-task-prompt.md / weekly-paid-prompt.md: 選ばれた見どころと「これも入れて」を `picks.json` に入れて深掘り担当・証券アナリストに渡す。
- 深掘り担当は見どころの裏取りと肉付けから始める。証券アナリストは選ばれた見どころを全部本文に入れる。PM のレビューに「選ばれた見どころが入っているか」を追加。
- note-pm.md のモード4・6: 候補に見どころの下調べ方針（何を調べると面白いか）を付ける。

## 2026-11-19 改訂: 視点ごとの4体分担と必須の組み合わせ（平日）

ユーザーと合意（案A②＋案B、統計担当の追加）。目的は、見どころが「数字」「他社比較」に偏るのを防ぎ、多様な視点から掘り下げること。

- **分担を候補ごとから視点ごとへ**: 数字・需給（note-jp-equity）／歴史・アノマリー（note-market-analyst。生活者目線・企業の物語も担当）／海外・マクロ（note-us-equity）／統計（note-quant、新設）。4体が全候補を見て、PM が `highlight_plan` で自分の視点に割り当てた項目だけを調べる（合う候補だけ）。
- `highlight_plan` は `[{"lens", "type", "what"}]` の形で各候補3〜4項目。1候補の中で同じ視点を2回使わない。効かない視点は割り当てない。
- **必須の組み合わせ**: 各候補に「数字（数字・統計）＋歴史か比較（歴史の事例・他社比較）＋意外か反対（意外な事実・反対の見方）」。`type` に「統計」「反対の見方」を追加。
- 検索の上限は1体あたり合計7回（4体で約28回。以前は2体で約20回）。締切 12:22・通知 12:30 は変えない。
- 検査とまとめは `note_pipeline/highlights.py`（空・推奨表現・重複を外し、必須3グループを先頭に、残りは視点を順番に回して各候補6点まで）。届かなかったグループは `missing` に出す。
- 統計担当は16:15の日次タスクでも、図と並行して下書きの数字の使い方を確かめる（`review/quant.md`、PM のレビュー項目8）。
- トークンの見込み: 見どころ下調べは以前の+25〜50%、候補出しタスク全体で+10〜15%。週末（候補5本）は従来どおり2体で、`highlight_plan` も文字列のまま。
