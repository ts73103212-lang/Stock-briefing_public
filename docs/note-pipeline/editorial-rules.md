# 編集ルール（全エージェント共通）

note `aicorgi_frank17` / X の記事を作るチームの共通ルール。各エージェントは作業の最初にこのファイルを読む。
設計書: `docs/superpowers/specs/2026-11-04-note-content-pipeline-design.md`

## 1. 法令・著作権（最優先）

- **投資助言に当たる表現を使わない。** 禁止:「買い」「売り」の推奨、「目標株価」「損切り」「利確」「推奨」「今がチャンス」「買い場」「必ず上がる」等。市場解説・データ分析・自分の視点の形にする。代わりに「論点」「データ上は」「私なら〜を確認する」を使う。
- 全記事の末尾に `<p><b>🐾投資判断はご自身で🐾</b></p>`。
- **新天地メルマガは「何が話題か」を知るシグナルとしてだけ使う。** 本文の転載・要約・言い換えを記事に載せない。メルマガを出典に挙げない。
- 記事本文・調査メモはリポジトリに書かない、コミットしない（公開リポジトリ）。作業ディレクトリ `WORK/` だけを使う。

## 2. 事実と出典

- 数字は**出典を確認できたものだけ**使う。調査メモには数字ごとに出典（媒体名・URL・日付）を付ける。
- 確認できない数字は「未確認」と書いて記事に使わない。銘柄の材料が裏付けできなければ、その銘柄は使わない。
- 日経平均の終値は、引けJSON（15:35取得）より**報道の大引け値を優先**し、差異があれば出典欄に記す。
- 引けJSONが古い・取得失敗のときは Web 検索で補完し、その値を使った図に「Web検索値」と明記する（spec の `"web_search": true`）。
- Yahoo Finance は環境のネットワーク設定で拒否・制限されることがある。取れなければ株探・日経・会社IR・TDnet 等の Web 検索で補う。

## 3. 文体

- 一人称「私」、です・ます調、落ち着いた解説口調。キャラクター名は名乗らない。
- 読者と同じ投資家目線。難しい概念はたとえ話で補う（このアカウントの強み）。
- 強気・弱気の両面を書く。煽らない。

## 4. テンプレート

### テーマ記事（kind: theme、2,000〜3,000字）
- タイトル: 疑問×テーマ型（例「〇〇が動いた理由 ─ △△から考える××」）
- はじめに: 今日起きたことを数字1つで示す
- 1. 数字で見る現状（図①: 型D または E）
- 2. たとえ話で仕組みを理解する（必要なら型F）
- 3. 関連する日本株（2〜3銘柄の表。データ紹介にとどめる／図②: 型C）
- 4. 私の見方・注意点
- 末尾: 有料記事への誘導の一文、Xへの誘導の一文、免責文

### 注目銘柄記事（kind: stock、2,000〜3,000字）
- タイトル: 銘柄名を先頭（例「【銘柄名(コード)】今日+18%の理由と、データが示す次の論点」）
- はじめに: 今日の値動きを一言で
- 1. 何が起きたか（材料・IR）
- 2. チャートで見る（株価＋出来高／図①: 型A）
- 3. 業績・バリュエーション（図②: 型B）
- 4. 見ておくべき論点（強気・弱気の両面）
- 末尾: テーマ記事と同じ

### 有料記事（kind: paid、7,000字級、図5〜6枚）
初回（中間選挙）の納品ページ https://claude.ai/artifact/JB4vSK8bM71sDAjsM4K6he が基準。
- 無料部分: はじめに → 1. 事実関係 → 2. 結論の方向性 → 有料部分で掘り下げる点の箇条書き → `<!--paywall-->`
- 有料部分: 深掘り（業績の逆算・歴史の教訓・たとえ話）→ 私が慎重／注目する理由 → 確認していく論点（表の図）→ おわりに → 計算方法と注意書き → 免責文

## 5. X投稿文（記事ごとに2案）

- 案1: 記事の要点を数字1つで示す（note のリンクは投稿時に足す）。案2: 問いかけ型。
- 140字以内、ハッシュタグ2個まで。売買指示（損切・目標価格など）を含めない。

## 6. 本文 HTML の書き方

- 使うタグ: `<h2>` `<h3>` `<p>` `<b>` `<ul><li>` `<blockquote>`。クラスや style は付けない。
- 図の位置に `<!--fig:1-->`（番号は記事内の通し番号）。有料記事は有料エリアの境界に `<!--paywall-->`。
- 本文の中で［図①］などを手書きしない（自動で入る）。
